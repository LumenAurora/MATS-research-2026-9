# Safety-SFT Trains a Template Reactor

MATS 12.0 (Machine Learning Reproducibility / Transparency Stream) mini research project.
20-hour study of what a controlled safety-SFT run actually changes in an agent that decides whether
a dangerous plan is *its* next action.

## TL;DR / main contribution

Under a strict evaluation protocol (held-out task quartets, teacher-forced labels, template-echo
detection, per-checkpoint isolation), a safety-SFT LoRA on Qwen3.5-4B-Base:

1. **generalizes refusal to unseen dangerous plans** (0/48 true executions at 1.00 and final epochs),
2. **collapses the benign side into *fake execution***: 0/48 true benign executions, 47-48/48 exact
   echoes of the training COMPLY template, and only 1/48 over-refusals.

Fake execution is a failure mode distinct from the over-refusal emphasized in the safety-alignment
literature. The model neither serves nor refuses a benign request, and a decoupled guard that scans
for refusal strings would score it as a successful completion. The trained policy is best described
as a content-gated *template reactor*, not a selective executor.

Dangerous content stays linearly readable across training (fixed base probe, L24 AUROC 0.888 at
base vs. 0.838-0.839 at 1.00/final): no deletion evidence.

This repository contains the report (LaTeX source + PDF + figures) and the code needed to reproduce
the data, training, evaluation, and statistics.

## How to reproduce

Requirements: Python 3, PyTorch + Transformers (tested on transformers 5.16.x),
peft (tested 0.20.0), scikit-learn, matplotlib, numpy. A CUDA GPU is required for training/eval.

### 1. Build data (no GPU needed)

```bash
cd code/data
python build_quartets_ext.py --base quartets_e1.json --out ../../data/quartets_ext.json
python build_safety_data_ext.py --quartets ../../data/quartets_ext.json \
    --out ../../data/safety_train_ext.jsonl --n_train 36
```

Both scripts assert on uniqueness (each frame: n_train*2 unique prompts, none empty); checks fail
loudly. (The committed `data/` files are generated by exactly these commands.)

### 2. Train

```bash
python code/train/train_lora.py --base <base_model_dir> \
    --data data/safety_train_ext.jsonl --out lora_v3 \
    --gpu 0 --checkpoints 0.50,1.00
```

### 3. Evaluate (strict protocol, per-checkpoint isolation)

```bash
# option A: clean, each checkpoint in its own process (use this for headline numbers)
bash code/eval/run_e3v2_refresh.sh
# option B: single-process orchestration (builds data + trains + evals)
bash code/eval/run_e3v2_ext.sh
```

Headline results (12 held-out quartets; 48 dangerous + 48 benign samples per checkpoint):

| ckpt | refuse(d) | real(d) | template(d) | real(b) | refuse(b) | template(b) |
|---|---|---|---|---|---|---|
| base  |  0/48 | 43/48 | 0 | 40/48 | 0 | 0 |
| 0.50  |  10   | 1     | 37 | 0     | 0 | 48 |
| 1.00  |  36   | 0     | 12 | 0     | 1 | 47 |
| final |  35   | 0     | 13 | 0     | 1 | 47 |

### 4. Statistics and figures (no GPU needed)

```bash
python code/analysis/stats_e3v2_refresh.py      # bootstrap CIs + McNemar (reads data/e3v2_ext.json)
python code/analysis/make_figures_en.py         # writes figures/*.png
```

## Audit trail (why these numbers are trustworthy)

Three pipeline bugs inflated early versions of these results. Each was found by hand re-deriving
numbers from raw rollouts, and each became a rule in the strict protocol:

1. **Empty training corpus** (E5): a role-balanced dataset read non-existent dictionary keys, so every
   prompt was empty. Fixed by a single shared serialization module (`messages.py`) with per-prompt
   assertions.
2. **Identical prompts in one frame** (E3): the self-commit frame lost the plan string during
   serialization, so 48 distinct tasks became 48 identical inputs. Fixed by uniqueness assertions.
3. **Checkpoint bleeding in evaluation** (found during this project's own re-audit):
   `PeftModel.from_pretrained(base, adapt).merge_and_unload()` in a loop writes the adapter delta
   back into the shared base model *in place*. Checkpoints evaluated after the first were therefore
   evaluated on polluted weights (base + earlier deltas). This is reproduced by
   `code/audit/check_pollution.py` (weight-norm difference ~1e4). The fix: evaluate each checkpoint
   in its own process from a fresh base load (`run_e3v2_refresh.sh`). The polluted run showed
   benign over-refusal 45/48 and a "collapsing" final checkpoint; the clean run shows 1/48
   over-refusal and monotone teacher-forced accuracy to 1.000.

Intervention and role-balanced experiments from earlier drafts (E2/E4/E5) are **withdrawn** from the
report: their interpretations depended on the invalidated corpora and on interventions lacking
random-direction sham controls. Their raw artifacts were kept for the audit trail.

## Reliability of the raw data

The dangerous behavior is simulated: a dummy tool environment, nothing executes. Raw rollouts were
hand-reviewed at every stage; the report includes verbatim examples from held-out quartets at the
start of the write-up (not cherry-picked; the first two held-out quartets in index order plus
fixed-seed base draws).
